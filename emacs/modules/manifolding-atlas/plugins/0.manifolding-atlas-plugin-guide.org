#+priority:   0
#+disabled:   t

This file is a complete reference for creating manifolding-atlas plugins in this
manifolding-emacs literate config. Give this file to any AI to generate
a new plugin from scratch with no other context.

* Quick Start
** Minimal Plugin File
Create =modules/manifolding-atlas/plugins/my-plugin.org=:

#+begin_src org
,#+title:      Manifolding Atlas My Plugin
,#+priority:   15

Description of what this plugin does.

,* State
,#+begin_src emacs-lisp
(defvar my/manifolding-atlas-my--state nil "Internal state.")
,#+end_src

,* Core
,#+begin_src emacs-lisp
(defun my/manifolding-atlas-my-do-thing ()
  "Do the thing."
  (interactive)
  (when-let ((note (my/manifolding-atlas--buffer-note)))
    (message "Note: %s" (manifolding-atlas-note-title note))))
,#+end_src
#+end_src

Then =M-x manifolding-emacs-reload= (or restart Emacs).

** Minimal Property Prompt
Creates a new metadata field that appears during note creation and in the
=SPC P= update menu.

1. Create =modules/manifolding-atlas/properties/my-field.org=:

#+begin_src org
,#+title:      My Field Prompt
,#+priority:   5

,* Prompt
,#+begin_src emacs-lisp
(defun my/manifolding-atlas-prompt-my-field ()
  "Prompt for MY_FIELD. Returns \"WARNING\" if skipped."
  (let ((val (completing-read "MY_FIELD: "
               '("⚠ WARNING" "VALUE_A" "VALUE_B")
               nil t nil nil "⚠ WARNING")))
    (if (string-equal val "⚠ WARNING") "WARNING" val)))

(my/manifolding-atlas-register-prompt
  :key 'my-field
  :name 'my-field
  :label "My: Field"
  :prompt-fn #'my/manifolding-atlas-prompt-my-field
  :contexts '(file heading)
  :read-current-fn (lambda () (org-entry-get nil "MY_FIELD"))
  :merge-strategy 'replace
  :to-plist (lambda (val _ctx)
              (when val
                `(:properties (("MY_FIELD" . ,val))
                  :post-apply (,(apply-partially #'my/manifolding-atlas--post-sync "MY_FIELD" val))))))
,#+end_src
#+end_src

2. Add a toggle in =modules/manifolding-atlas/plugins/properties-update.org= so it
   appears in the =SPC P= menu. Find the =(my/manifolding-atlas--define-toggle ...)=
   block and add:

#+begin_src emacs-lisp
(my/manifolding-atlas--define-toggle my-field my-field)
#+end_src

Then add it to the transient prefix menu in the same file:

#+begin_src emacs-lisp
;; In the transient-define-prefix, add under an existing [group]:
("f" my/manifolding-atlas--toggle-my-field)
#+end_src

3. If you want schema validation, add the field to the base schema in
   =modules/manifolding-atlas/plugins/schemas.org= (see *Schema definitions*).

* Complete Working Plugin Example
This section shows a complete, real plugin that you can create directly.
It registers a DB extractor, defines a schema, and provides UI commands.

Create =modules/manifolding-atlas/plugins/30.my-review-plugin.org=:

#+begin_src org
,#+title:      Manifolding Atlas Review Plugin
,#+priority:   15

Tracks review dates for notes. Each note gets a REVIEW_DATE property.
Provides a transient menu to mark notes as reviewed and query overdue notes.

,* State
,#+begin_src emacs-lisp
(defvar my/manifolding-atlas-review--overdue-threshold 30
  "Days after which a note is considered overdue for review.")
,#+end_src

,* Database Table
,#+begin_src emacs-lisp
(defun my/manifolding-atlas-review--ensure-table ()
  "Create review_dates table if it does not exist."
  (emacsql (manifolding-atlas-db)
    [:create :table :if :not :exists review_dates
     ([(note-id :not-null)
       (review-date :not-null)]
      (:primary-key [note-id])
      (:foreign-key [note-id] :references notes [id]
       :on-delete :cascade))]))
,#+end_src

,* DB Extractor
,#+begin_src emacs-lisp
(defun my/manifolding-atlas-review--extract (ctx note-data)
  "Extract REVIEW_DATE from note properties and store in review_dates table."
  (let* ((note-id (plist-get note-data :id))
         (props (plist-get note-data :properties))
         (review-date (cdr (assoc "REVIEW_DATE" props))))
    ;; Delete old row, insert current value
    (emacsql (manifolding-atlas-db)
      [:delete :from review_dates :where (= note-id $s1)]
      note-id)
    (when review-date
      (emacsql (manifolding-atlas-db)
        [:insert :into review_dates :values $v1]
        (vector note-id review-date)))
    note-data))

(with-eval-after-load 'manifolding-atlas
  (my/manifolding-atlas-review--ensure-table)
  (manifolding-atlas-db-register-extractor
   (make-manifolding-atlas-extractor
    :name       'review-dates
    :version    1
    :priority   80
    :extract-fn #'my/manifolding-atlas-review--extract)))
,#+end_src

,* Mark as Reviewed
,#+begin_src emacs-lisp
(defun my/manifolding-atlas-review--mark-reviewed (&optional note)
  "Set REVIEW_DATE on NOTE (or current buffer note) to today."
  (interactive)
  (let* ((note (or note (my/manifolding-atlas--buffer-note)))
         (date (format-time-string "<%Y-%m-%d %a>")))
    (unless note (user-error "No note at point"))
    (my/manifolding-atlas--property-put note "REVIEW_DATE" date)
    (message "✓ Review date set to %s" date)))
,#+end_src

,* Overdue Query
,#+begin_src emacs-lisp
(defun my/manifolding-atlas-review--overdue-notes ()
  "Return list of manifolding-atlas-note objects whose last review is overdue."
  (let* ((cutoff (format-time-string "%Y-%m-%d"
                  (time-subtract (current-time)
                    (days-to-time my/manifolding-atlas-review--overdue-threshold))))
         (rows (emacsql (manifolding-atlas-db)
                [:select [notes:*]
                 :from notes
                 :inner :join review_dates
                 :on (= notes:id review_dates:note-id)
                 :where (< review_dates:review-date $s1)]
                cutoff)))
    (mapcar #'manifolding-atlas-db--row-to-note rows)))
;; Note: manifolding-atlas-db--row-to-note is internal but safe to use here
;; since it's the same function used by manifolding-atlas-db-query internally.

(defun my/manifolding-atlas-review--show-overdue ()
  "Display all overdue notes in a buffer."
  (interactive)
  (let ((notes (my/manifolding-atlas-review--overdue-notes)))
    (if (not notes)
        (message "No overdue notes!")
      (with-current-buffer (get-buffer-create "*review-overdue*")
        (erase-buffer)
        (insert (format "Overdue Reviews (%d notes)\n\n" (length notes)))
        (dolist (n notes)
          (insert (format "  [[id:%s][%s]]\n"
                          (manifolding-atlas-note-id n)
                          (manifolding-atlas-note-title n))))
        (display-buffer (current-buffer))))))
,#+end_src

,* Transient Menu
,#+begin_src emacs-lisp
(require 'transient)

(transient-define-prefix my/manifolding-atlas-review--menu ()
  "Review actions for the current note."
  [["Review"
    ("r" "Mark reviewed" my/manifolding-atlas-review--mark-reviewed)
    ("o" "Show overdue"  my/manifolding-atlas-review--show-overdue)]])
,#+end_src
#+end_src

* How manifolding-emacs loads files
This section is based on the actual source in =lisp/manifolding-emacs.el=.

** File discovery (source: manifolding-emacs.el lines 494-503)
=manifolding-emacs-get-files= calls =directory-files-recursively= on
=modules/= (the value of =manifolding-emacs-org-directory= which defaults
to =(expand-file-name "org" user-emacs-directory)=), matching the regexp
=^[^#]*\.org$=. Files starting with =#= are excluded. All found files are
sorted by their =#+priority:= value (default 10, lower loads first).

** Evaluation (source: manifolding-emacs.el lines 402-451, 464-492)
=manifolding-emacs-compile-file= does two things for each .org file:

1. **Package extraction** (lines 408-437): Scans every heading for
   =:PACKAGE:= =:STRAIGHT:= =:CATEGORY:= =:DEPENDS:= properties. These
   are converted to =use-package= or =leaf= forms and collected separately.

2. **Source block concatenation** (lines 438-451): Uses
   =org-babel-map-src-blocks= to find every =#+begin_src emacs-lisp= block.
   Blocks with a =:PACKAGE= property on their heading are treated as package
   configuration (merged into the package declaration). Blocks without a
   package property are wrapped in =(condition-case err (progn ...) (error ...))=
   and concatenated in order.

3. **Evaluation** (lines 476-491): The concatenated source + package forms
   are combined and passed to =(eval (read (format "(progn\n%s\n)" output)))=.

Key behaviors:
- Only =emacs-lisp= source blocks are evaluated.
- Blocks are evaluated in order they appear, top to bottom.
- Text between source blocks is ignored at load time (documentation only).
- The entire file is wrapped in a single =progn=, so =defvar=, =defun= etc.
  are all available to later blocks in the same file.
- =#+disabled: t= skips the file entirely.

** Remote files (source: manifolding-emacs.el lines 528-542)
Files with a =#+remote:= property are downloaded from GitHub before
compilation. Not used for manifolding-atlas plugins.

* File naming and structure
** Naming convention
Plugin files live in =modules/manifolding-atlas/plugins/= and are named:

  N.short-description.org

Where N is a two-digit sort key (e.g. 10, 15, 20). Since plugins all
use =#+priority: 15=, the filename prefix doesn't affect load order
within the plugins directory.

* File-level properties
These are =#+KEY: VALUE= lines at the top of the file. Recognized by
manifolding-emacs (source: manifolding-emacs.el lines 172-205):

| Property                   | Required | Default | Purpose                                  |
|----------------------------+----------+---------+------------------------------------------|
| #+title:                   | yes      | —       | Human-readable plugin name               |
| #+priority:                | no       | 10      | Load order (lower = earlier)              |
| #+disabled:                | no       | nil     | Set to 't' to skip this file             |
| #+lexical_binding:          | no       | t       | Set to 'nil' if code needs dynamic scope |
| #+header-args:emacs-lisp:  | no       | nil     | Set babel header defaults for all blocks  |

The =capture-plugin.org= file uses =#+header-args:emacs-lisp: :tangle manifolding-atlas-capture.el=
to tangle its code into a standalone =.el= file. Normally you don't need
this — manifolding-emacs evaluates source blocks directly.

* Package declarations
To declare packages (straight.el packages), use a PROPERTIES drawer on
the same heading as a source block. Properties recognized:

| Property    | Value format              | Purpose                       |
|-------------+---------------------------+-------------------------------|
| :PACKAGE:   | package-name              | Name of the package          |
| :STRAIGHT:  | (pkg :type git :host ...) | Straight recipe              |
| :CATEGORY:  | category-name             | Org category (documentation) |
| :DEPENDS:   | (dep1 dep2)              | Dependencies for straight    |

Each PROPERTIES drawer can declare ONE package. For multiple packages,
add multiple PROPERTIES drawers after each other on the same heading.

Example — two packages in one file (from =backup-git.org=):

#+begin_src org
:PROPERTIES:
:PACKAGE:  magit
:STRAIGHT: (magit :type git :host github :repo "magit/magit" :depends (git-gutter) :files (...))
:CATEGORY: git
:PACKAGE:  git-gutter
:END:
#+end_src

The package is installed via straight.el automatically. If the package
is already required in =modules/manifolding-atlas.org=, you can skip the
declaration and just use =(require 'my-package)= directly.

* Source block patterns
** Basic emacs-lisp block (evaluated normally)
#+begin_src emacs-lisp
(message "Hello from plugin")
#+end_src

** Block with lexical binding
#+begin_src emacs-lisp :lexical t
(let ((x 1))
  (lambda () x))
#+end_src

** Block with :tangle (generates a separate .el file, NOT evaluated by manifolding)
#+begin_src emacs-lisp :tangle my-plugin.el
;;; my-plugin.el --- standalone file
#+end_src

** Block excluded from evaluation
#+begin_src emacs-lisp :tangle no
;; installation instructions only
#+end_src

** What NOT to do
- Do NOT put non-code text inside source blocks.
- Do NOT use :session (each block is evaluated independently).
- Do NOT use :exports or :noweb unless necessary.
- Do NOT use :results (it has no effect — the output is not used).

** Pattern 3: Advice (before/after/around)
Advice on existing Emacs or manifolding-atlas functions. Examples from this config:

*** The =manifolding-atlas-note-meta-get-list= fallback (from =properties-update.org= lines 119-144):
This is the most important advice in the config. Schema validation reads
from description lists (=manifolding-atlas-note-meta-get-list=), but this config
stores values in property drawers. This advice bridges the gap:

#+begin_src emacs-lisp
(defun my/manifolding-atlas--meta-get-fallback (orig-fun note prop &optional type)
  "Fall back to the property drawer when the description list has no value for PROP."
  (or (funcall orig-fun note prop type)
      (when (memq type '(nil string))
        (when-let* ((file (manifolding-atlas-note-path note))
                    (key (if (symbolp prop) (symbol-name prop) prop))
                    (val (if (and (buffer-file-name)
                                 (equal (file-truename (buffer-file-name))
                                        (file-truename file)))
                             (save-excursion
                               (when-let ((pos (manifolding-atlas-note-pos note)))
                                 (ignore-errors (goto-char pos)))
                               (org-entry-get nil key))
                           (with-current-buffer (find-file-noselect file)
                             (save-excursion
                               (when-let ((pos (manifolding-atlas-note-pos note)))
                                 (ignore-errors (goto-char pos)))
                               (org-entry-get nil key))))))
          (unless (string-empty-p val)
            (list val))))))

(advice-add 'manifolding-atlas-note-meta-get-list :around #'my/manifolding-atlas--meta-get-fallback)
#+end_src

an advice on =manifolding-atlas-note-meta-get-list= falls back to the property drawer
when the description list has no value (the =my/manifolding-atlas--meta-get-fallback=
advice in =properties-update.org= lines 119-144).

** Direct SQL access via emacsql
For custom tables, use (emacsql (manifolding-atlas-db) ...) with s-expression syntax.
The emacsql library provides a Lispy SQL syntax:

#+begin_src emacs-lisp
;; Create table with foreign key to notes table
(emacsql (manifolding-atlas-db)
  [:create :table :if :not :exists my_table
   ([(id :not-null) (value :not-null)]
    (:primary-key [id])
    (:foreign-key [id] :references notes [id]
     :on-delete :cascade))])

;; Insert rows (using $v1 for vector parameter)
(emacsql (manifolding-atlas-db)
  [:insert :into my_table :values $v1]
  (list (vector "id1" "val1") (vector "id2" "val2")))

;; Insert with :or :ignore (skip if primary key exists)
(emacsql (manifolding-atlas-db)
  [:insert :or :ignore :into my_table :values $v1]
  (vector note-id parent-id order-key node-type depth))

;; Query (using $s1 for scalar parameter)
(emacsql (manifolding-atlas-db)
  [:select [value] :from my_table :where (= id $s1)]
  "target-id")

;; Select all columns using notes:*
(emacsql (manifolding-atlas-db)
  [:select [notes:*]
   :from notes
   :inner :join my_table
   :on (= notes:id my_table:note-id)
   :where (= my_table:value $s1)]
  "some-value")

;; Delete
(emacsql (manifolding-atlas-db)
  [:delete :from my_table :where (= id $s1)]
  "target-id")

;; Update
(emacsql (manifolding-atlas-db)
  [:update my_table
   :set [(= value $s1)]
   :where (= id $s2)]
  "new-val" "target-id")

;; Aggregate (count, min, max, etc.)
(emacsql (manifolding-atlas-db)
  [:select [(funcall count *)]
   :from my_table
   :where (= value $s1)]
  "some-value")

;; Group by
(emacsql (manifolding-atlas-db)
  [:select [key (funcall count note-id)]
   :from my_table
   :group :by key
   :order :by [(desc (funcall count note-id))]])
#+end_src

Always use foreign keys with =ON DELETE CASCADE= to automatically clean
up when notes are removed from the database. The =notes= table is the
canonical reference table. Its primary key is =id= (a UUID string).

Foreign key reference patterns used by existing plugins:
- citation.org: =(note-id :not-null) = references notes [id] on-delete cascade
- transclusion.org: dual foreign keys for source and dest
- manifold.org: =(note-id :text :primary-key :not-null) = with foreign key to notes [id]

The =:extract-fn= is called with two arguments:

*** Pattern A: Extract from AST (requires-ast t)
From =citation.org= lines 24-47. Walks the AST for paragraphs containing
=[@citekey]= patterns:

#+begin_src emacs-lisp
(defun my/manifolding-atlas-extract-citations (ctx note-data)
  "Extract [@citekey] citations from org paragraphs in CTX."
  (let* ((ast     (manifolding-atlas-parse-ctx-ast ctx))
         (note-id (plist-get note-data :id))
         (found   nil))
    (org-element-map ast 'paragraph
      (lambda (para)
        (let ((text  (org-element-interpret-data para))
              (start 0))
          (while (string-match "\\[@\\([^]]+\\)\\]" text start)
            (push (match-string 1 text) found)
            (setq start (match-end 0))))))
    (when found
      (let ((unique (delete-dups (nreverse found))))
        (emacsql (manifolding-atlas-db)
          [:delete :from citations :where (= note-id $s1)]
          note-id)
        (emacsql (manifolding-atlas-db)
          [:insert :into citations :values $v1]
          (mapcar (lambda (k) (vector note-id k)) unique))
        (plist-put note-data :citations unique)))
    note-data))

(with-eval-after-load 'manifolding-atlas
  (my/manifolding-atlas-citations-ensure-table)
  (manifolding-atlas-db-register-extractor
   (make-manifolding-atlas-extractor
    :name       'citations
    :version    2
    :priority   50
    :requires-ast t      ; MUST declare this since extract-fn calls manifolding-atlas-parse-ctx-ast
    :extract-fn #'my/manifolding-atlas-extract-citations)))
#+end_src

** Key patterns for extractors (source: manifolding-atlas-db-extract.el lines 237-270)
1. ALWAYS delete before insert for the current note's rows before writing
   new ones. The row may already exist from a previous sync.

2. Use =(emacsql (manifolding-atlas-db) [:delete :from my_table :where (= note-id $s1)] note-id)=
   before inserting fresh data.

3. Use =:insert :or :ignore= when you want to preserve existing rows
   (from =manifold.org=).

4. Always set =(:foreign-key [note-id] :references notes [id] :on-delete :cascade)=
   on plugin tables so cleanup is automatic.

5. Bump =:version= when the extraction logic changes to force
   re-extraction of all notes.

6. Use =:priority= to control execution order relative to other extractors.
   Lower numbers run first (default 100).

7. Declare =:requires-ast t= when your extractor calls
   =(manifolding-atlas-parse-ctx-ast ctx)=. Without this, the AST slot is nil
   and your extractor silently produces nothing.

8. For extractors that read from note-data only (no AST), do NOT declare
   =:requires-ast=. This keeps extraction fast and worker-eligible.

9. Extractors should return the enriched (or unmodified) NOTE-DATA plist.
   A nil return = "use note-data as it now stands" (per source).

Each field in a schema is a plist:

| Key         | Required | Value type            | Purpose                                  |
|-------------+----------+-----------------------+------------------------------------------|
| :key        | yes      | string                | Metadata key (e.g. "STATE_WORK")         |
| :type       | no       | symbol                | 'string (default), 'number, 'symbol, 'note, 'link |

Violation types (source: manifolding-atlas-schema.el lines 372-379):
- =missing-required= — a required field has no value

** The WARNING sentinel pattern: Central Design Decision
This is the most important convention in the config:

1. When a user **skips** a prompt during note creation (presses RET
   on the default "⚠ WARNING" option), the value stored in the
   property drawer is literally the string ="WARNING"=.

2. The schema field validation flags ="WARNING"= as a violation:
   =(lambda (val _note) (if (equal val "WARNING") "missing-required" t))=.
   This means: "the prompt was skipped, so this metadata is effectively
   missing."

3. =manifolding-atlas-schema-collection-health= detects these violations and
   =my/manifolding-atlas-missing--rebuild-from-health= writes them to
   =MISSING PROMPTS= so you can fix them later.

4. The =my/manifolding-atlas--fix-violations= command (bound to =SPC P= or
   the MISSING PROMPTS click) prompts for each WARNING-valued
   field and lets you replace it with a real value.

5. The migration function =my/manifolding-atlas-schema-migrate-warnings=
   deletes old ="WARNING"= sentinels from the vault (making the
   properties truly absent, which the schema then flags as
   missing-required).

ALWAYS include "⚠ WARNING" as the default in your completing-read
prompt, and ALWAYS return "WARNING" when the user skips. This is how
the system tracks incomplete metadata.

** Property drawer vs description list
Schema validation reads from the *description list* (the =::= values in
Org). But this config stores metadata in the *property drawer* (=:PROP:=).
A compatibility advice bridges the gap (defined in =properties-update.org=
lines 119-144 — see the full code in Pattern 3 above).

This means validation works with property drawer values even though
the manifolding-atlas API reads from the description list.

** Toggle suffix pattern (used by =properties-update.org=)
The =properties-update.org= plugin generates toggle suffixes using a macro.
This pattern allows checkboxes that the user toggles before confirming:

#+begin_src emacs-lisp
;; State variables
(defvar my/manifolding-atlas--selected-keys nil
  "List of :key symbols toggled for update.")

;; Macro that generates toggle commands
(defmacro my/manifolding-atlas--define-toggle (key name)
  "Define a Transient toggle suffix for prompt KEY with function NAME."
  (let ((fname (intern (format "my/manifolding-atlas--toggle-%s" name))))
    `(transient-define-suffix ,fname ()
       :description (lambda () (my/manifolding-atlas--update-format-prompt ',key))
       (interactive)
       (if (memq ',key my/manifolding-atlas--selected-keys)
           (setq my/manifolding-atlas--selected-keys (delq ',key my/manifolding-atlas--selected-keys))
         (push ',key my/manifolding-atlas--selected-keys))
       (transient-setup 'my/manifolding-atlas--update-properties-menu))))

;; Define toggles for each prompt
(my/manifolding-atlas--define-toggle tags tags)
(my/manifolding-atlas--define-toggle state-work state-work)
;; ... one per prompt

;; Confirm — run all selected prompts
(transient-define-suffix my/manifolding-atlas--update-confirm ()
  "Run all selected prompts and apply changes."
  (interactive)
  (let ((keys my/manifolding-atlas--selected-keys))
    (setq my/manifolding-atlas--selected-keys nil)
    (dolist (key keys)
      (let (spec val frag)
        (setq spec (my/manifolding-atlas--update-prompt-spec key))
        (setq val (condition-case nil
                     (funcall (plist-get spec :prompt-fn))
                   (quit nil)))
        (when (and (stringp val) (string-equal val "WARNING"))
          (setq val nil))

** The prompt registry (from =properties/00-register.org=)

(defvar my/manifolding-atlas-prompt-registry nil
  "List of prompt specs. Each spec is a plist with:
:key           SYMBOL   — unique identifier (same as :name)
:name          SYMBOL   — unique identifier (alias for :key)
:label         STRING   — human-readable display name for Transient UI
:prompt-fn     FUNCTION — (&optional current) -> raw value from the user
:contexts      LIST     — '(file heading task ...)
:to-plist      FUNCTION — (VAL CONTEXT) -> plist fragment
:read-current-fn FUNCTION — () -> current value from the visited buffer
:validate-fn   FUNCTION or nil — (VAL) -> non-nil means valid
:merge-strategy SYMBOL  — 'replace | 'merge | 'append

Fragment keys:
:tags         (list of strings)      — merged by append
:properties   (alist)                — merged by append
:body         (string)               — concatenated
:post-apply   (list of functions)    — each called with the note
:after        nil or 'last           — heading insert position")

(defun my/manifolding-atlas-register-prompt (&rest plist)
  "Register a prompt spec PLIST into `my/manifolding-atlas-prompt-registry'."
  (unless (plist-get plist :key)
    (setq plist (plist-put plist :key (plist-get plist :name))))
  (unless (plist-get plist :name)
    (setq plist (plist-put plist :name (plist-get plist :key))))
  (push plist my/manifolding-atlas-prompt-registry))

** Context types
- =file= : file-level notes (level 0) — prompts run during file note creation
- =heading= : heading-level notes (level > 0) — prompts run during heading creation
- =task= : notes with "task" tag — prompts with different defaults for tasks

** =:prompt-fn= signature
The prompt function is called with no arguments (or an optional =current=
initial value). It must return one of:

| Return value   | Meaning                                              |
|----------------+------------------------------------------------------|
| "WARNING"      | User skipped the prompt (sentinel for schema tracking)|
| A string       | Property value to store                              |
| A list         | Multiple values (for tags, aliases)                  |
| A plist        | Structured return (like mind-map's (:placement ...)) |
| nil            | No change (skip)                                     |

** =:to-plist= return value (the fragment plist)
The =:to-plist= function converts the raw prompt value into a "fragment"
plist that describes what changes to apply to the note. Supported keys:

| Key           | Value type              | Purpose                                  |
|---------------+-------------------------+------------------------------------------|
| :properties   | alist (KEY . VAL)       | Set property drawer entries               |
| :tags         | list of strings         | Set or merge tags                         |
| :todo         | string or nil           | Set TODO state                            |
| :body         | string                  | Append body text                          |
| :post-apply   | list of functions       | Functions called with the note after apply|
| :after        | nil or 'last            | Heading insert position                   |
| :file-name    | string                  | File name override (creation only)        |

** The update pipeline (from =properties-update.org=)
1. User invokes =my/manifolding-atlas-update-properties= (bound to SPC P)
   or clicks a heading in MISSING PROMPTS
2. Opens the note's file, positions at the heading
3. Opens the Transient toggle menu
4. User toggles which properties to update (creates =my/manifolding-atlas--selected-keys= list)
5. User presses =C-c C-c= to confirm
6. For each selected prompt:
   a. Look up the prompt spec via =my/manifolding-atlas--update-prompt-spec=
   b. Call =:prompt-fn= to get the new value
   c. Skip ="WARNING"= returns (no change)
   d. Call =:to-plist= to get a fragment
   e. Apply the fragment via =my/manifolding-atlas--apply-fragment=
7. Buffer is saved

** The note creation flow (from =manifolding-atlas.org=)
When a new note is created via =manifolding-atlas-create=, the following happens:

1. =my/manifolding-atlas-collect-prompts= is called with the context ('file, 'heading, or 'task)
2. For each registered prompt matching the context:
   a. The help file is shown (via =my/manifolding-atlas--show-help=)
   b. The prompt function is called
   c. The result is converted to a fragment via =:to-plist=
   d. Tags, properties, body, post-apply, and :after are accumulated
3. The accumulated properties/tags are passed to =manifolding-atlas-create=
4. After creation, =:post-apply= functions are called with the new note
5. The =my/manifolding-atlas--open-in-capture= advice (filter-return on manifolding-atlas-create)
   records the source relationship and opens org-capture for body editing

#+begin_src emacs-lisp
;; The collector function (from manifolding-atlas.org lines 634-667)
(defun my/manifolding-atlas-collect-prompts (context)
  "Run all registered prompts matching CONTEXT and merge results."
  (let (result)
    (dolist (spec my/manifolding-atlas-prompt-registry)
      (when (memq context (plist-get spec :contexts))
        (my/manifolding-atlas--show-help (plist-get spec :name))
        (let (val frag)
          (setq val (condition-case nil
                        (funcall (plist-get spec :prompt-fn))
                      (quit nil)))
          (setq frag (funcall (plist-get spec :to-plist) val context))
          (when-let ((v (plist-get frag :tags)))
            (setq result (plist-put result :tags
                         (append (plist-get result :tags) v))))
          (when-let ((v (plist-get frag :properties)))
            (setq result (plist-put result :properties
                         (append (plist-get result :properties)
                                 (cl-remove-if (lambda (p) (string-empty-p (cdr p))) v)))))
          (when-let ((v (plist-get frag :body)))
            (setq result (plist-put result :body
                         (concat (or (plist-get result :body) "") v))))
          (when-let ((v (plist-get frag :post-apply)))
            (setq result (plist-put result :post-apply
                         (append (plist-get result :post-apply) v))))
          (when-let ((v (plist-get frag :after)))
            (setq result (plist-put result :after v)))
          (when-let ((v (plist-get frag :file-name)))
            (setq result (plist-put result :file-name v)))
          (when (plist-member frag :todo)
            (setq result (plist-put result :todo (plist-get frag :todo))
                  my/manifolding-atlas--creation-todo (plist-get frag :todo))))
        (my/manifolding-atlas--close-help)))
    result))
#+end_src

#+begin_src emacs-lisp
(defun my/manifolding-atlas--set-file-property (key value strategy)
  "Set KEY to VALUE in the file-level property drawer using STRATEGY."
  (save-excursion
    (goto-char (point-min))
    (if (re-search-forward "^:PROPERTIES:$" nil t)
        (let ((end (save-excursion
                     (or (re-search-forward "^:END:$" nil t) (point-max)))))
          (goto-char (match-end 0))
          (if (re-search-forward (format "^:%s: ?" (regexp-quote key)) end t)
              (if (string-empty-p value)
                  (delete-region (line-beginning-position) (1+ (line-end-position)))
                (when (eq strategy 'replace)
                  (replace-match (format ":%s: %s" key value) t t)))
            (unless (string-empty-p value)
              (re-search-forward "^:END:$" nil t)
              (beginning-of-line)
              (insert (format ":%s: %s\n" key value)))))
      (unless (string-empty-p value)
        (insert ":PROPERTIES:\n")
        (insert (format ":%s: %s\n" key value))
        (insert ":END:\n")))))

** The =my/manifolding-atlas--apply-fragment= helper (from =properties-update.org= lines 253-303)
Applies a fragment plist (as returned by a prompt's =:to-plist=) to the
current buffer:

#+begin_src emacs-lisp
(defun my/manifolding-atlas--apply-fragment (frag spec)
  "Apply FRAG plist from SPEC to the current buffer."
  (let ((strategy (or (plist-get spec :merge-strategy) 'replace))
        (at-heading (org-at-heading-p)))
    (unless at-heading
      (setq at-heading (ignore-errors (org-back-to-heading t) t))
      (unless at-heading
        (setq at-heading (ignore-errors (org-next-visible-heading 1) t))))
    ;; Handle :todo
    (when (plist-member frag :todo)
      (let ((todo (plist-get frag :todo)))
        (if (and (stringp todo) (not (string-empty-p todo)))
            (progn
              (org-todo todo)
              (org-entry-delete nil "TODO"))
          (save-excursion
            (org-back-to-heading t)
            (org-entry-delete nil "TODO")
            (let ((case-fold-search nil))
              (looking-at org-complex-heading-regexp)
              (replace-match
               (concat (match-string 1) " " (match-string 4)
                       (when (match-string 5)
                         (concat " " (match-string 5))))
               t t))))))
    ;; Handle :tags
    (when-let ((tags (plist-get frag :tags)))
      (if at-heading
          (pcase strategy
            ('merge (org-set-tags (cl-union (org-get-tags nil t) tags :test #'string=)))
            ('replace (org-set-tags tags)))
        (user-error "Tags on file-level notes not supported yet")))
    ;; Handle :properties
    (when-let ((props (plist-get frag :properties)))
      (dolist (pair props)
        (if at-heading
            (let ((v (cdr pair)))
              (if (string-empty-p v)
                  (org-entry-delete nil (car pair))
                (pcase strategy
                  ('merge (unless (org-entry-get nil (car pair))
                            (org-entry-put nil (car pair) v)))
                  ('replace (org-entry-put nil (car pair) v)))))
          (my/manifolding-atlas--set-file-property (car pair) (cdr pair) strategy))))
    ;; Handle :body
    (when-let ((body (plist-get frag :body)))
      (save-excursion
        (goto-char (point-max))
        (insert "\n" body)))
    ;; Handle :post-apply
    (when-let ((fns (plist-get frag :post-apply)))
      (dolist (fn fns)
        (funcall fn my/manifolding-atlas--current-note)))))
#+end_src

* Description lists (metadata)
manifolding-atlas's =meta= API reads from Org description lists. These are plain
Org lists of the form:

  - key :: value

Description lists live in the note's body, NOT in the property drawer.

** The two storage systems
This config uses a hybrid approach:
- **Creation-time prompts** store values in the **property drawer**
  via =org-entry-put=. These are readable via =org-entry-get= and
  appear in =(manifolding-atlas-note-properties note)=.
- **manifolding-atlas's meta API** reads from **description lists** via
  =(manifolding-atlas-note-meta-get-list note ...)=. This is what schema validation
  uses.
- The =my/manifolding-atlas--meta-get-fallback= advice bridges the two: when
  schema validation looks for a description list value and finds none,
  it falls back to the property drawer.

* complete plugin file checklist
Every plugin file should have:
1. =#+title:= — human-readable name
2. =#+priority: 15= — loads after core manifolding-atlas.org
3. Source blocks organized under logical headings
4. All functions use =my/manifolding-atlas-= prefix
5. Internal functions use =my/manifolding-atlas--= (double dash)
6. One plugin per file, named descriptively

* Testing a new plugin
1. Write the plugin file in =modules/manifolding-atlas/plugins/=
2. Run =M-x manifolding-emacs-reload= (or restart Emacs)
3. Check the =*Messages*= buffer for errors
4. Test interactive commands
5. If using a DB extractor, trigger a manifolding-atlas resync:
     =M-x manifolding-atlas-db-sync-force=
6. For property prompts, create a new note and check the prompt flow
7. For schema validation, use =M-x my/manifolding-atlas-check-vault= to see the
   schema collection health
8. Test the update menu with =SPC P= (or =M-x my/manifolding-atlas-update-properties=)

* Troubleshooting
** "Symbol's value as variable is void: ..."
Caused by =let= evaluating variable bindings in parallel. Use =let*=
for sequential binding:

Wrong:
  (let ((a (compute-x))
        (b (1+ a)))   ; ERROR: a not bound yet
    ...)

Right:
  (let* ((a (compute-x))
         (b (1+ a)))
    ...)

** "Wrong type argument: commandp"
The symbol is not =(interactive)= or was defined in a different
context. Make sure interactive functions have =(interactive)= and
that transient suffixes are defined with =transient-define-suffix=.

** "Symbol's function definition is void: manifolding-atlas-*"
The manifolding-atlas package hasn't loaded yet. Wrap code in:
  (with-eval-after-load 'manifolding-atlas
    ...)

** Plugin not loaded
Check:
1. File is in =modules/manifolding-atlas/plugins/=
2. Does not start with =#= in filename
3. Does not have =#+disabled: t=
4. Has =#+priority:= set (but any value works)
5. Run =M-x manifolding-emacs-reload= or restart Emacs

** "Cannot open load file: transient"
Add =(require 'transient)= before your transient definitions.

** Schema violations not detected
Check:
1. =manifolding-atlas-db-schema-validation-action= is not =silent=
2. The schema's predicate matches your note
3. The field's =:key= matches the property drawer key
4. The property value is actually stored (use =org-entry-get= to verify)
5. The =my/manifolding-atlas--meta-get-fallback= advice is active (=properties-update.org=)

** WARNING values not being flagged
Check that your schema field's =:validate= function checks for "WARNING":

  :validate (lambda (val _note)
               (if (equal val "WARNING") "missing-required" t))

** Extractor not running
Check:
1. Is the extractor registered via =manifolding-atlas-db-register-extractor=?
2. Is registration wrapped in =(with-eval-after-load 'manifolding-atlas ...)=?
3. Does =:requires-ast= match your extract-fn? (t if using AST, unset/nil if not)
4. Did you run =M-x manifolding-atlas-db-sync-force= to trigger extraction?
5. Did you bump =:version= after changing extraction logic?

** Database table creation order
If you register multiple extractors that depend on each other's tables,
ensure the table-creating extractor has lower =:priority= (runs first).
Extractors with the same priority run in registration order.

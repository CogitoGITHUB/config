* Overview
Manifolding Atlas is the personal [[https://github.com/d12frosted/vulpea][vulpea]]-derived note management
system for this [[../../][manifolding-emacs]] literate Emacs config. It is a fully local,
literate port: the upstream vulpea library, vulpea-ui UI layer and
consult-vulpea completion front-end are **vendored** verbatim as `.org`
source files under =core/= and evaluated directly by the
`manifolding-emacs` boot loader — none of them are installed via
`straight`/`leaf` recipes (only their external dependencies are).

```text
  manifolding-emacs (loader)
  └─ modules/*.org  — sorted by #+priority: (lower = earlier)
      └─ manifolding-atlas/          ← THIS module tree
          ├─ core/                   priorities -31 … -13  (vendored engine)
          ├─ manifolding-atlas.org   priority 10           (entry/config)
          ├─ manifolding-atlas-ui.org / consult-manifolding-atlas.org (UI config)
          ├─ manifolding-atlas-functions/  priority 12      (user extensions)
          ├─ plugins/                priority 10/15/…       (feature plugins)
          ├─ properties/             priority -1 …          (metadata prompts)
          └─ templates/              priority 10            (doct + yasnippet)
```

Why it exists / architecture decisions:

- The package is **loader-managed**, not `straight`-managed. The vendored
  source is evaluated as loose elisp source blocks; only real external deps
  (`dash`, `s`, `emacsql`, `vui`, `consult`) are `:STRAIGHT:` packages.
- Everything was renamed from `vulpea` → `manifolding-atlas` uniformly
  (dirs, files, symbols, features, DB). `vulpea-ui` → `manifolding-atlas-ui`,
  `consult-vulpea` → `consult-manifolding-atlas`, `my/vulpea-*` →
  `my/manifolding-atlas-*`.
- All personal/custom code uses the `my/` namespace and, internally,
  `my/manifolding-atlas--` (double dash for private helpers). No comments are
  added to source blocks.

* Quick Facts
- **Notes directory:** `~/test/` — from `(my/manifolding-atlas-root-dir)` → `"/home/aoeu/test/"`.
  The single source of truth for the vault location (edit only this function).
- **Database:** `~/test/admin/manifolding-atlas.db` (SQLite via `emacsql`),
  root-owned `root:users 664`, git-excluded (see `~/.config/emacs/.gitignore`
  and `~/test/.gitignore`). Managed by the Atlas SQLite layer — never edit by hand.
- **DB sync:** external method `fswatch`, auto-sync enabled.
- **Main feature:** `manifolding-atlas` (provided by =core/-15=). Complements:
  `manifolding-atlas-ui`, `consult-manifolding-atlas`.
- **Key commands:** `manifolding-atlas-find`, `manifolding-atlas-insert`,
  `manifolding-atlas-find-backlink`, `manifolding-atlas-ui-sidebar-toggle`,
  `consult-manifolding-atlas-find`, `consult-manifolding-atlas-insert`.
- **Reload:** `M-x manifolding-emacs-reload` (or via Emacs MCP `eval-elisp`).

* File/Layout Conventions
- **Feature/namespace prefixes:** `manifolding-atlas-*`,
  `manifolding-atlas-ui-*`, `consult-manifolding-atlas-*`, `my/*`.
- **`#+priority:`** controls load order (lower = earlier; negatives allowed).
  See each file's header — always keep the numeric priority in the filename
  in sync with the `#+priority:` keyword.
- **No blank line after headings** at any level.
- Each vendored core file keeps its upstream `(provide '…)` verbatim; the
  trailing `;;; file.el ends here` banner was stripped.

* =properties/ — Property Prompts (metadata)
Registered prompts that fire during capture (file/heading/task contexts) and
appear in the `SPC P` update menu. `00-register.org` must load first.

- **`00-register.org`** (39, priority -1): the prompt registry
  `my/manifolding-atlas-prompt-registry` + `my/manifolding-atlas-register-prompt`.
  Resets the registry to nil on every reload to prevent duplicate accumulation.
- **`general/`** — file/heading-level metadata prompts:
  `file-name`, `subdir`, `tags`, `aliases`, `position` (insert position, headings
  only), `priority`, `schedule` (Scheduled/Deadline), `todo` (TODO state), `properties`
  (extra), `mastering`, `mind-map`, plus the **state** family: `state-general`,
  `state-work`, `state-intelligence`, `state-operational`, `state-validation`,
  `state-source`, `state-checklist`, `state-dependency`. Each has an `AGENTS.md`
  under `general/`.

  State prompts are required at creation (skipping sets `"WARNING"`, tracked via
  MISSING PROMPTS).
- **`dictionary/`** — vocabulary metadata prompts: `etymology`, `examples`
  (Example Sentence), `frequency`, `pos` (part of speech), `pronunciation`,
  `register`, `synonyms`.
- **`rules/`** — rule metadata prompts: `scope`, `level`, `topic` (Rule Topics),
  `file-override`.
- Each subdir carries its own `AGENTS.md`.

* =templates/ — Capture & Snippet Templates
Entry config: `templates/manifolding-atlas-templates-system.org` (43 lines).

- **org-capture (doct)** → `full-file-templates/*.org`, triggered by
  `manifolding-atlas-create` → preview select → org-capture. Body-only templates
  (no `*` heading, no `#+title:` — headingification creates `* Title` first).
  Selection stores `:TEMPLATE:` / `:TEMPLATE_HASH:` for schema validation.
  Template preview pane renders with `%?` → the note's title.
  - `notes.org` — `** Notes` + list.
  - `task.org` — `** Objective` checkbox + `** Notes`.
  - `reference.org` — `:ROAM_REFS:` + `** Summary`, `** Claims`, `** Connections`.
  - `protocol.org` — `** Purpose`, `** Materials`, `** Procedure`, `** Results`, `** Analysis`, `** Notes`.
  - `math.org` — `** Definition/Theorem/Lemma/Proof/Properties/Notes` (LaTeX `\begin{…}`).
  - `manifolding-atlas.el` (doct declaration) defines the capture tree (`n` = new note / task / heading) bound to function `my/manifolding-atlas-capture-*`.
- **yasnippet** → `snippets/` (currently empty dir, ready for snippets).
- **`templates/AGENTS.md`** documents both engines.

* How It Loads
1. `bootstrap.org` → `init.el` loads `manifolding-emacs`.
2. `manifolding-emacs-boot` → `manifolding-emacs-compile-directory` scans
   `modules/` recursively for `.org`, sorts by `#+priority:` (default 10, lower first),
   and evaluates each file's loose elisp src blocks (per-file
   `:PACKAGE:`/`:STRAIGHT:` handled via the leaf builder).
3. For this module: `core/` (-31 … -13) runs first, pulling in deps and defining the
   engine; then `manifolding-atlas.org` / `manifolding-atlas-ui.org` /
   `consult-manifolding-atlas.org` (10); then `manifolding-atlas-functions/` (12) and
   the plugins (10/15); `properties/00-register.org` (-1) runs before the prompt files.
4. Verify: `(featurep 'manifolding-atlas)`, `(featurep 'manifolding-atlas-ui)`,
   `(featurep 'consult-manifolding-atlas)`; `(manifolding-emacs-errors-list)`.
   Reload with `M-x manifolding-emacs-reload`.

* Conventions for contributors
- **Namespace:** `my/` (user), `my/manifolding-atlas--` (internal), never bare `vulpea`.
- **No comments** in source blocks unless asked.
- **No blank line** after headings.
- Keep filename priority prefix in sync with `#+priority:`.
- For a new plugin, start from `plugins/0.manifolding-atlas-plugin-guide.org`.
- For a new property prompt, drop a file in `properties/` (it auto-registers via
  `prompt-infrastructure.org` + `my/manifolding-atlas-register-prompt`); put `00-register.org`
  first in load order.
- DB is Atlas-managed. Add plugin tables via `[:create :table ...]` in `:config` and an
  extractor for sync (see `citation.org`, `mastering-atlas.org`, `transclusion.org` as examples).
